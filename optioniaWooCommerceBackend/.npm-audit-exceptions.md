# Accepted audit advisories

`npm audit --omit=dev --audit-level=high` fails the build, deliberately. This
file records the advisories that are accepted anyway, and why — so the check
stays strict rather than being lowered to `critical` to make one finding go away.

⚠️ **An entry here is a claim about reachability, not a dismissal.** Each one
states the code path the advisory needs and why this codebase does not have it.
If that stops being true, the entry is wrong and the exception must go.

---

## multer ≤ 2.2.0 — two denial-of-service advisories

- [GHSA-wc9g-mqfw-jrwm](https://github.com/advisories/GHSA-wc9g-mqfw-jrwm) — DoS via crafted multipart field names
- [GHSA-qfvm-cv95-jqjf](https://github.com/advisories/GHSA-qfvm-cv95-jqjf) — DoS via file descriptor leak on aborted uploads

**Accepted 2026-09-22.**

🔴 **Both require a multipart upload endpoint, and this API has none.** Verified
rather than assumed: `src/` contains no `FileInterceptor`, no `FilesInterceptor`,
no `@UploadedFile`, and no multipart handling of any kind.

📌 **Customer file uploads never reach this API.** M15 ships them, and they stay
on the merchant's own WordPress — `src/usage/` records storage *totals* for plan
limits, not the bytes. The plugin's API client posts no file.

⚠️ **It is transitive and cannot be fixed in isolation.** `multer` arrives via
`@nestjs/platform-express@11`, and the first NestJS release shipping a patched
`multer@2.4.0` is **12** — a major bump across eleven `@nestjs` packages, with
its own breaking changes, for a code path nothing calls.

**This exception expires when either is true:**

1. A route accepts multipart input — then the advisory is live and NestJS 12
   becomes urgent, not optional.
2. The project adopts NestJS 12 for its own reasons — then delete this section
   and let the check pass on its merits.
